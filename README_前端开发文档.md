# 会计事务所资料收集系统 - 前端开发文档

## 1. 文档用途

本文把[系统架构设计](./README_系统架构设计.md)拆成可执行的前端开发阶段，并与[后端开发文档](./README_后端开发文档.md)对应。Mock 可以帮助阶段内并行开发，但每个阶段的最终验收必须连接真实后端 API。

前端仓库：`acc-system-frontend`

技术基线：Vue 3、TypeScript、Vite、shadcn-vue、Pinia、Vue Router、Vue I18n、Axios、`axios-case-converter`、pnpm。

## 2. 开发与验收规则

### 2.1 通用完成标准

每个阶段同时满足以下条件才算完成：

1. `pnpm lint` 和 `pnpm build` 通过，不能用关闭规则或 TypeScript 检查规避真实错误；
2. 本阶段新增的状态、字段转换和权限显示逻辑有最小自动测试；
3. 最终验收连接对应阶段的真实后端，不以 Mock 响应代替；
4. 页面覆盖 loading、空数据、成功、业务错误、网络错误和无权限状态；
5. 表单有 label、键盘可操作、清晰焦点和可读错误提示，状态不能只靠颜色表达；
6. 所有 HTTP 请求通过统一 Axios client，不在组件内直接使用 `fetch` 或新建 Axios 实例；
7. 验收记录保存测试日期、前后端提交 SHA、镜像标签、浏览器和失败截图。
8. 用户可见文案不直接写在组件中；英文消息必须完整，缺失翻译回退到英文。

### 2.2 状态与接口规则

- Pinia 只保存认证状态和少量跨页面 UI 偏好；
- 列表筛选、分页和排序写入 URL query；
- 页面业务数据从 API 获取，不建立第二套客户端数据库；
- access JWT 只保存在请求模块的内存变量，不写 localStorage/sessionStorage；Pinia 保存用户资料与认证状态；
- refresh JWT 只由 HttpOnly Cookie 携带；
- API snake_case 与前端 camelCase 只在 Axios 边界转换；
- portal 与会计端使用不同响应类型，前端不依赖后端内部字段；
- 按钮是否显示只改善体验，权限与状态最终由后端判断。
- Vue I18n 默认 locale 和 fallback locale 都是 `en`，简体中文使用 `zh-CN`；
- 仅在用户主动切换后保存 locale 偏好；新浏览器和无偏好用户始终先显示英文；
- API 返回稳定的错误码和枚举值，前端负责翻译展示文案，不翻译协议字段和值。

### 2.3 建议命令

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm build
pnpm test # F2 开始
docker build -t acc-system-frontend:local .
```

Playwright 只在最终关键流程需要浏览器自动化时加入；组件和纯逻辑优先使用 Vitest，避免首版维护大规模脆弱的端到端套件。

## 4. F1：部署基线

### 4.1 阶段目标

先确认当前 Vue 工程可以稳定构建成镜像，经 ECR 发布并由服务器上的总入口 Nginx 访问。本阶段不实现登录和业务页面。

### 4.2 交付内容

- 保留多阶段 Dockerfile：Node/pnpm 构建，静态 Web Server 运行；
- 固定 Node 与 pnpm 版本，使用 `pnpm-lock.yaml` 和 `--frozen-lockfile`；
- 静态容器监听内部端口，不直接映射服务器公网端口；
- 静态服务支持 SPA fallback，刷新 `/login` 等前端路由不会返回 404；
- `.dockerignore` 排除 node_modules、dist、Git 和本地环境文件；
- GitHub Actions 在 PR 执行构建，在 main/tag 使用 AWS OIDC 推送 ECR；
- 镜像使用 Git SHA 不可变标签；
- 前端运行配置首版只使用同域 `/api/v1`，不把生产后端域名编译进镜像；
- 页面提供最小的构建版本信息，便于确认当前部署 SHA。

本阶段不增加组件库封装、状态管理、测试框架或业务路由；这些从 F2 开始按实际需要加入。

### 4.3 验收前置

- B1 的 Compose 与总入口 Nginx 已可运行；
- frontend ECR repository 和 GitHub OIDC 变量已配置；
- 服务器 `.env` 已固定 `FRONTEND_IMAGE` 的 SHA 标签。

### 4.4 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F1-A1 | 执行 `pnpm install --frozen-lockfile && pnpm lint && pnpm build` | ESLint、TypeScript 和构建通过并生成 dist |
| F1-A2 | 构建并启动前端镜像，直接请求容器根路径 | 返回 Vue 页面，容器不需要 Node 开发服务器 |
| F1-A3 | 通过总入口 Nginx 请求 `/` 和 `/login`，并刷新 `/login` | 两个地址都返回 SPA，刷新不出现 Nginx 404 |
| F1-A4 | 请求 `/api/v1/health/live` | 请求由 Nginx 转发给 backend，不被前端 fallback 截获 |
| F1-A5 | 推送 main 后查看 GitHub Actions 与 ECR | 构建通过，ECR 出现对应 Git SHA 标签，无长期 AWS key |
| F1-A6 | 服务器固定新 SHA 并执行 Compose pull/up | 页面展示的构建 SHA 与部署值一致；切回旧 SHA 可以恢复上一镜像 |
| F1-A7 | 检查最终镜像 | 不包含源码仓库、node_modules、`.env` 或构建凭据；仅暴露内部静态服务端口 |

### 4.5 阶段完成标志

任一前端提交都能生成可追踪的不可变镜像，并通过后端仓库维护的 Compose/Nginx 在服务器上访问。

## 5. F2：应用骨架、Axios 与登录

### 5.1 阶段目标

建立后续页面共用的路由、布局、认证和请求边界，一次解决 JWT 刷新、字段命名转换与错误处理。

### 5.2 交付内容

- 安装并配置 Vue Router、Pinia、Vue I18n、Axios、`axios-case-converter`；
- 建立 `en` 与 `zh-CN` 消息文件；默认和 fallback 均为 `en`，页面文案、校验提示、状态与错误码统一使用翻译 key；
- 语言切换集中在账户设置中，不占用登录页、工作台或 404 的页头；持久化 locale，并同步更新根元素的 `lang` 属性；
- 账户设置提供常青绿（默认）、石板灰、蓝色配色，以及浅色、深色、跟随系统（默认）三种显示模式；偏好保存到当前浏览器；
- 外观在首屏绘制前初始化；跟随系统模式实时响应系统外观变化，登录页、工作台、Select 菜单和 404 共用主题色；
- `src/api/client.ts` 是唯一请求入口，业务 Axios 实例和无 refresh 重试的会话实例共用 `baseURL=/api/v1`、`withCredentials=true`；
- 请求 data/params 转 snake_case，响应 data 转 camelCase，headers、FormData、File 和 Blob 不被破坏；
- auth store 将 access JWT 同步到请求模块的内存变量，request interceptor 从内存读取；不写入浏览器持久化存储；
- response interceptor 使用共享 refresh Promise，并发 401 只刷新一次，每个原请求最多重试一次；
- 应用启动时调用 refresh 恢复会话，失败后进入未登录状态；
- `/login`、会计端 layout、客户端 portal layout 和 404 页面；
- 路由 meta 区分公开页、事务所端和客户端；
- 登录、退出、修改密码和当前用户页面；
- 统一处理 401、403、404、409、422、429 和 5xx；`request_id` 在错误详情中可复制；
- Vitest 覆盖字段转换、refresh 并发和重试终止条件。

### 5.3 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F2-A1 | 使用有效账号登录 | 跳转到角色对应首页；access JWT 仅存在内存，浏览器存储中不存在 token |
| F2-A2 | 刷新浏览器或重新打开页面 | 依靠 HttpOnly Cookie 恢复会话，用户无需重复输入密码 |

| F2-A5 | ACCOUNTANT 和 CLIENT_SUBMITTER 分别访问对方路由 | 前端给出无权限页面或正确跳转；直接调用 API 仍由后端拒绝 |
| F2-A6 | 提交带嵌套对象、数组和 query 的请求 | API 收到 snake_case，组件获得 camelCase；Authorization/Idempotency-Key 未被改名 |

| F2-A10 | 切换到简体中文后刷新，再模拟一个缺失的中文翻译 key | 刷新后保持 `zh-CN`；缺失项显示英文 fallback，不显示原始 key |
| F2-A11 | 在账户设置分别选择三种配色及浅色/深色，访问工作空间和 404 后刷新 | 配色和模式保持，页面、输入框和 Select 菜单均正确适配，无大块固定白色背景 |

| F2-A13 | 保存深色偏好后重新打开页面 | 首屏按深色显示，不先闪现浅色；无偏好时使用常青绿和跟随系统 |

### 5.4 阶段完成标志

后续页面只调用领域 API 模块，不再处理 token、refresh、字段转换、通用错误或自行维护界面文案。

## 6. F3：账户与客户管理

### 6.1 阶段目标

让事务所管理员维护员工、客户、联系人和负责人，让客户管理员维护本客户联系人。

### 6.2 交付内容

- `/app/admin/users`：员工列表、邀请、启用/禁用；
- `/app/clients`：客户列表、搜索、分页和状态；
- `/app/clients/:id`：基本信息、业务特征、银行账户、联系人和会计分配；
- CLIENT_ADMIN 可见的联系人管理入口；
- 邀请状态、过期、撤销和重新邀请反馈；
- 固定角色选择，不实现自定义 RBAC 编辑器；
- 表单提交期间禁止重复点击，409/422 显示可行动说明；
- 无权限动作不显示，但仍正确处理后端返回的权限错误。

### 6.3 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F3-A1 | FIRM_ADMIN 创建客户并邀请会计和客户管理员 | 列表和详情立即反映状态，受邀者能完成 B2 邀请流程 |
| F3-A2 | 为客户分配/取消分配会计 | 页面显示最新负责人；受影响会计刷新后访问范围同步变化 |
| F3-A3 | CLIENT_ADMIN 邀请本客户联系人 | 操作成功且只能选择客户端角色 |
| F3-A4 | ACCOUNTANT 或 CLIENT_SUBMITTER 尝试打开管理员页面 | 导航不显示入口，直接输入 URL 得到无权限结果 |
| F3-A5 | 快速重复点击邀请或保存 | 只产生一次有效请求，不生成重复邀请或重复客户 |
| F3-A6 | 列表翻页后进入详情再返回 | URL 中的搜索、分页和筛选条件保留 |
| F3-A7 | 后端返回 409/422/429 | 页面保留用户输入并显示明确处理方式，不只弹出“请求失败” |

### 6.4 阶段完成标志

管理员无需数据库或 SQLAdmin 即可完成首版账户、客户和负责人维护。

## 7. F4：会计端收集请求

### 7.1 阶段目标

让会计人员从待办列表创建和发布月度资料收集请求，并能稳定跟踪进度和历史事件。

### 7.2 交付内容

- `/app/dashboard`：待我审核、等待客户、即将到期、已逾期；
- `/app/collections`：服务端分页，按客户、期间、状态、负责人和截止日筛选；
- 筛选、分页和排序写入 URL query；
- 桌面端列表右侧详情面板，窄屏直接进入完整详情；
- `/app/collections/new`：客户、期间、截止日、说明和 requirements 一次提交；
- 请求详情显示状态、版本、负责人、要求、提交轮次和事件；
- 业务动作按钮：保存草稿、发布、复制上月、取消；不提供任意状态下拉框；
- 写操作生成并复用一次 `Idempotency-Key`，网络重试不生成新 key；
- version 冲突显示最新数据和刷新入口，不静默覆盖。

### 7.3 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F4-A1 | 会计创建包含多个 requirement 的草稿 | 保存成功，详情显示完整要求和 DRAFT 状态 |
| F4-A2 | 必填项缺失或后端校验失败 | 定位到具体字段，用户输入保留，不产生半张请求 |
| F4-A3 | 发布请求后刷新页面 | 状态为 OPEN，显示发布事件；已发布要求不再出现删除入口 |
| F4-A4 | 网络超时后重试发布 | 前端复用同一 Idempotency-Key，最终只显示一次发布事件 |
| F4-A5 | 两个浏览器编辑同一草稿 | 后提交者收到版本冲突提示，可查看最新数据后重新操作 |
| F4-A6 | 复制上月请求到新期间 | 表单预填 requirements，但不展示为已上传或已审核 |
| F4-A7 | 组合筛选列表、打开详情再返回 | URL 和列表位置保持，数据只包含当前用户有权访问的客户 |

### 7.4 阶段完成标志

会计可以从 Dashboard 找到工作、创建并发布真实请求，刷新、重试和多人操作不会造成不明确状态。

## 8. F5：客户门户、文件上传与首次提交

### 8.1 阶段目标

让客户清楚知道缺什么、已经上传什么，并能安全完成首次提交。退回原因和补交轮次在 F6 与审核流程一起验收。

### 8.2 交付内容

- `/portal/collections` 与 `/portal/collections/:id`；
- 顶部显示期间、截止日、负责人、整体进度和当前状态；
- requirement 可展开，显示说明、已上传文件、处理状态和公开审核意见；
- 上传区绑定 requirement，并提供“其他支持文件”；
- Axios `onUploadProgress` 显示进度，上传完成后轮询 `QUARANTINED → AVAILABLE/FAILED`；
- 草稿文件可逻辑排除，已提交文件不能从历史中消失；
- 页面底部主动作“提交审核”；F6 接入补交状态后复用为“再次提交”；
- 提交前列出未上传或仍需处理的必填项，但最终判断以后端结果为准；
- 网络中断支持明确重试，不把同一文件显示成多个成功上传；
- portal 类型中不存在 internalNote 和 AI 原始输出字段。

### 8.3 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F5-A1 | 客户打开一个 OPEN 请求 | 看见期间、截止日、所有要求和明确的待办状态 |
| F5-A2 | 上传正常文件 | 显示上传进度，随后展示扫描中，最终变为可用 |
| F5-A3 | 上传超限、类型不符或扫描失败文件 | 显示明确失败原因和重新上传入口，文件不能被预览/下载 |
| F5-A4 | 文件尚在 QUARANTINED 时尝试提交 | 页面提示仍在处理；绕过前端提交时以后端规则为准 |
| F5-A5 | 上传多个文件、排除一个并提交 | 确认页只列出有效文件，提交后当前轮次变为只读 |
| F5-A6 | 客户尝试访问另一个客户的 URL 或 document id | 不显示任何目标数据，错误页不泄漏资源是否存在 |
| F5-A7 | 检查页面响应和开发者工具 | 看不到 internalNote、AI 原始输出、文件磁盘路径或其他事务所字段 |
| F5-A8 | 使用键盘选择文件、查看错误并提交 | 核心操作无需鼠标即可完成，状态同时有文字/图标而非仅颜色 |

### 8.4 阶段完成标志

客户可以在门户中完成首次资料提交；F6 再完成退回说明和多轮补交闭环。

## 9. F6：会计审核、审批与上线验收

### 9.1 阶段目标

完成会计审核工作台、证据检索和最终审批，并用少量稳定的浏览器测试覆盖关键业务闭环。

### 9.2 交付内容

- `/app/collections/:id/review` 三块区域：要求列表、文件预览/提取字段、审核动作；
- 活动时间线作为同页 tab/drawer；
- 当前和历史材料按期间、类型检索并关联为证据；
- 单项满足、要求补交和豁免；公开客户说明与内部备注分开输入和展示；
- 整单要求补交、批准、管理员撤回批准和关闭；
- 按当前状态和角色映射展示可用动作，但不在前端复制完整状态机，后端仍作最终判断；
- AI 建议使用独立标识，必须点击“采纳并填写审核决定”才进入人工表单；
- version 冲突时保留未提交文字并提示加载最新状态；
- 对破坏性动作、豁免、批准、撤回和关闭使用确认弹窗；普通单项审核不重复确认；
- 关键路径 Playwright：登录、创建发布、客户上传提交、退回补交、审核批准；
- 桌面与常用窄屏宽度的可用性、焦点、错误和空状态检查。

### 9.3 可验收场景

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| F6-A1 | 会计审核客户提交的错主体文件 | 文件保留，requirement 显示 `NEEDS_ACTION` 和公开原因，内部备注只在事务所端可见 |
| F6-A2 | 搜索并关联历史期间发票支持本期付款 | 审核页展示关联关系，不产生重复文件 |
| F6-A3 | 多份文件共同支持一个 requirement | 要求列表和文件区都能定位所有证据，审核后关系仍存在 |
| F6-A4 | 尚有必填项未满足时点击批准 | 按钮不可用或后端拒绝；页面指出未满足项，状态不变 |
| F6-A5 | 全部满足后批准，再由管理员撤回 | 进入 READY_FOR_BOOKKEEPING；撤回需填写原因并返回 IN_REVIEW，时间线完整 |
| F6-A6 | 两名会计同时审核同一项 | 后提交者看到 409 冲突和最新状态，未提交备注可复制/恢复，不覆盖他人结果 |
| F6-A7 | AI 返回建议、超时和非法响应 | 合法建议只作提示；超时/非法响应有独立错误，不阻塞人工审核 |
| F6-A8 | 通知服务不可用 | 页面业务操作照常成功，通知失败不被显示成审批失败 |
| F6-A9 | 完整执行“创建发布 → 上传 → 退回 → 补交 → 满足 → 批准” | 前后端真实环境闭环成功，Playwright 关键路径通过 |
| F6-A10 | 使用 CLIENT_SUBMITTER 检查同一请求 | 只看见公开意见和允许动作，看不到内部备注、AI 原文和管理按钮 |
| F6-A11 | 用键盘操作审核动作和确认弹窗，并在窄屏查看 | 焦点不会丢失或困住，错误可读；窄屏仍能完成审核 |

### 9.4 阶段完成标志

前端覆盖账户、会计工作台和客户门户的首版完整流程。暂不加入流程画布、看板、自定义视图编辑器、离线模式和前端生成式 AI；出现明确业务需求后再评估。
